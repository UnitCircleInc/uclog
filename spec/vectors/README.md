# Protocol test vectors

Generated by [`../reference/gen_vectors.py`](../reference/gen_vectors.py) from the reference
implementation. **Do not edit by hand.** Change the generator, regenerate, and commit both.

```sh
python3 spec/reference/gen_vectors.py          # regenerate
python3 spec/reference/gen_vectors.py --check  # CI: fail if out of date
python3 spec/reference/check_vectors.py        # CI: run the vectors against the reference
```

Every implementation (Rust crates, TypeScript `@uclog/core`, the Python library) runs these
files in its own test suite. [`check_vectors.py`](../reference/check_vectors.py) shows how to
read each file.

All byte strings are lowercase hex. Every file has a `description` field.

| File | protocol.md | Contents |
|---|---|---|
| `cobs.json` | §2.1 | `valid`: encode/decode pairs, including the 254-byte boundary cases. `invalid`: inputs that must fail to decode |
| `scanner.json` | §2.2 | byte chunks → frame / oversize events: split reads, pulses, garbage before sync, oversize discard |
| `peek_mux.json` | §3 | payload → encoded frame → 2-byte peek result and full mux decode, for every frame type and the special ports |
| `logs.json` + `sample.logdata` | §3.3, §6, §7 | wire bytes → decoded `{level, file, line, text}` for every argument kind, enums, sym lookup, mem dumps, `<zephyr>` text, flags/width, string escaping. `errors`: the error kind expected |
| `fw_update.json` | §5.4 | every FW update request/reply as CBOR, as port-59 wire bytes, and as legacy port-3 wire bytes; CRC-32C check value |
| `semihost.json` | §5.5 | request parsing (incl. WRITE bit 31 and the 31-bit fid), time-op replies for POSIX and Windows clock sources (incl. SYS_CLOCK wrap), error replies, newlib errno table |
| `links.json` | §4 | HID output report chunking, HID input example, STLINK split writes |
| `device_info.json` | §5.2 | a port-62 frame with a 64-byte `app_hash` |

Notes for runners:

- **CBOR byte equality.** Where a vector gives CBOR bytes, the encoder used shortest-form
  integers, definite lengths, insertion-order map keys and float64. Compare **decoded values**
  for anything received. Compare bytes only when your encoder makes the same choices.
- **Logs.** `text` must match exactly for the `logs.json` cases. Decoders that fail must produce
  an error record of the listed kind; the exact text is up to the UI (§7).
- **`sample.logdata`.** `fns` uses CBOR **array keys** (`[low, size]`). Make sure your CBOR library
  accepts non-text map keys.
